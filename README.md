# IziWork — посадочная страница и собственный трекинг

Один проект на Next.js и TypeScript: публичный мобильный сайт, закрытая `/admin`, PostgreSQL, серверные перенаправления, рекламные источники, QR и отчёты. Встроенная PostgreSQL-совместимая PGlite используется для локального запуска и автоматических тестов; на VPS используется обычный PostgreSQL. Обязательных платных API нет.

Репозиторий содержит только исходный проект: сайт, административную панель, миграции, тесты и инструкции. Рабочая база, статистика, кампании и источники действующей установки, учётные записи администраторов, пароли, ключи, резервные копии и снимки отчётов в него не входят. Новая установка создаёт собственную пустую базу; существующий сайт и его данные остаются на своём сервере.

Текущий режим работает без баннера согласия, аналитических cookies посетителя и загрузки Метрики. Серверный учёт входов и кликов сохраняется; источник связан с кликом подписанным токеном страницы. При повторной загрузке без cookies может создаваться новая оценочная сессия. Для отдельного режима необязательной аналитики предусмотрен серверный флаг `OPTIONAL_ANALYTICS_ENABLED=true`: только в этом режиме доступны баннер и сохранение сессии после выбора посетителя. По умолчанию флаг выключен; один лишь ввод ID Метрики его не включает. Cookies входа администратора независимы от этого флага.

**До публикации:** замените ссылки и юридические плейсхолдеры, создайте администратора, настройте резервные копии и проверьте [чек-лист владельца](docs/privacy-launch.md). Демонстрационные источники помечены как тестовые. Готовых паролей и публичной регистрации нет.

## Быстрый локальный запуск

Требуются Node.js 24 и pnpm 11.25.0 (версия зафиксирована в `packageManager`). Из корня проекта:

```powershell
corepack enable
Copy-Item .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Вставьте полученное значение в `AUTH_SECRET`, сгенерируйте другое для `POSTBACK_SECRET`. Оставьте `DATABASE_URL=pglite://./.data/postgres` и `APP_URL=http://localhost:3000`. Затем:

```powershell
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm admin:create
pnpm dev
```

Публичный сайт: [http://localhost:3000](http://localhost:3000). Вход: [http://localhost:3000/admin](http://localhost:3000/admin), с созданными в CLI email и паролем. CLI запрашивает пароль; для автоматизации поддерживаются `ADMIN_EMAIL` и `ADMIN_PASSWORD` в окружении процесса. Не записывайте производственный пароль в Git, историю команд или общее `.env`.

Для необязательной проверки демонстрационных источников выполните `pnpm db:seed`. Команда создаёт четыре источника `spb01`, `spb02`, `twitch01`, `vkpub01` с признаком **тестовых**, без искусственных посещений и кликов. Для пустой рабочей установки эту команду пропустите. Рабочие источники создавайте без тестового признака. PGlite хранится в `.data/postgres`; не запускайте несколько процессов приложения с одним каталогом PGlite и не используйте этот режим как многосерверную производственную БД.

Для проверки производственной сборки локально остановите dev-сервер и выполните:

```powershell
pnpm check
pnpm test
pnpm build
$env:ALLOW_PGLITE_PRODUCTION = 'true'
pnpm start
```

`ALLOW_PGLITE_PRODUCTION=true` разрешает только этот локальный просмотр production build со встроенной БД. На VPS не задавайте его: производственная конфигурация требует PostgreSQL. Для bash аналог: `ALLOW_PGLITE_PRODUCTION=true pnpm start`. Тесты используют отдельную БД и не должны направляться на производственный `DATABASE_URL`.

Для переноса исходников с Windows можно выполнить `powershell -File scripts/package.ps1`: архив появится в `artifacts/`. В него входят код, миграции, документация и `.env.example`; рабочие секреты, локальная база, зависимости и сборка не включаются. На чистом VPS настройте собственный `.env` и создайте отдельного администратора.

`pnpm build` выполняет `next build --webpack`, `pnpm dev` также использует webpack. Этот вариант проверен в текущем Windows-окружении с Next.js 16.4.3. Сборка создаёт обычный `.next`, без режима standalone.

## Как получить первый QR

Общие короткие адреса `/vk`, `/tg`, `/max` сразу перенаправляют соответственно на `https://vk.ru/alekseevich143`, `https://t.me/alekseevich_job`, `https://max.ru/u/f9LHodD0cOIhdWgnjYqFrMRhiGpvLv-tvsh11QEkyXB5PGk4bTvc6XxyO1U`. Эти адреса закреплены без изменений в `src/lib/direct-social.ts`; параметры запроса и настройки бот-ссылок не меняют конечный URL. Новые GET-переходы привязаны к рабочему источнику «Офлайн / Баннеры» с постоянным кодом `offline_banners` и печатным кодом `banners`. При новой установке создайте такой источник в админке; в рабочей базе он уже подготовлен. В его карточке и печатных макетах отображаются именно `/vk`, `/tg`, `/max`. Учитываются входящий и прямой целевой переходы без посещения лендинга и без посадочной сессии; HEAD только перенаправляет. Источник баннеров имеет приоритет над UTM, сами метки сохраняются внутри аналитики и не добавляются к конечному адресу. Это учёт рекламного адреса, а не доказательство ручного ввода. Старые события без источника автоматически не переатрибутируются.

1. Войдите в `/admin`, откройте настройки ссылок и укажите действующие HTTPS-адреса VK, Telegram и MAX.
2. Создайте кампанию с названием, категорией «Офлайн» или «Онлайн» и необязательным бюджетом.
3. Создайте источник: постоянный код, короткий печатный код, площадка, размещение и кампания. Категория автоматически наследуется из кампании и отдельно не редактируется. Без кампании категорию можно задать вручную. Расходы — фактическая стоимость размещения.

Изменение категории кампании обновляет категории всех её источников одной транзакцией. При переносе источника в другую кампанию применяется её категория. Если у кампании категория не выбрана, у её источников она тоже пуста, в таблице отображается «Не выбрана». Для старых пустых и смешанных кампаний выберите категорию через «Изменить». Источники без кампании позволяют выбирать категорию самостоятельно. Коды, ссылки, расходы и записи событий при изменении категории не переписываются. Фильтр категории использует текущую категорию источника.

Кнопки VK, Telegram и MAX на лендинге и в окне связи открываются в новой вкладке через внутренний маршрут `/go/площадка?token=…&newtab=1`. Лёгкая промежуточная страница сохраняет лендинг в истории новой вкладки и затем выполняет обычный серверный трекинг. «Назад» возвращает на лендинг без повторного автоматического перехода; исходная вкладка остаётся открыта. Сам промежуточный документ не создаёт клик или визит. При переходе в установленное приложение дальнейшей навигацией управляют приложение и браузер.

В окне «Изменить» кампании и источника доступно **полное удаление** с вводом названия кампании или постоянного кода источника. `DELETE /api/admin/campaigns|sources` требует действующей админской сессии, Origin, CSRF, `{id, confirmation}` и ограничивает частоту запросов. Кампания удаляется вместе со всеми текущими источниками, а также относящимися к ней историческими событиями и подтверждениями. Удаляются переходы, подтверждения, постоянные коды и история ссылок. Сессии других источников сохраняются, их атрибуция восстанавливается по оставшимся событиям. Старые подробные записи журнала удаляются; остаётся только краткая запись об операции с количеством удалённых строк, без названий, кодов и URL. После удаления источника его рекламные ссылки и QR перестают работать. Файлы QR генерируются на лету и на сервере не накапливаются.

Удаление применяется к рабочей базе одной транзакцией. Защищённые резервные копии удаляются по своему сроку хранения. PostgreSQL повторно использует освобождённые страницы после очистки; физический размер файла базы не обязан сразу уменьшиться.
4. Откройте карточку источника. Основной URL имеет вид `https://ваш-домен/r/код`. Скачайте QR в PNG или SVG; для типографии предпочтителен SVG. Сохраняйте белое поле и печатайте чёрным по белому.
5. Рядом с QR можно напечатать `/v/код`, `/t/код`, `/m/код`. Эти адреса ведут прямо в соцсеть. Они учитываются отдельно и не создают посещение лендинга.
6. Проверьте реальный отпечаток камерой iPhone и Android перед тиражом. A5/A6 скачиваются как SVG с физическим размером листа; откройте макет в браузере или редакторе и при печати выберите соответствующий формат, масштаб 100% и отключите колонтитулы.

Код и печатный код после создания изменить нельзя: переименование источника и смена конечных ссылок не меняют напечатанный URL. Задайте нужный короткий код сразу при создании источника. После изменения домена уже напечатанный QR автоматически не меняется: прежний домен придётся сохранять и перенаправлять самостоятельно. PNG/SVG доступны в размере от 128 до 4096 пикселей, массовый ZIP — до 100 источников за раз и содержит оба формата плюс таблицу адресов.

Все вновь скачиваемые QR автоматически содержат логотип IziWork по центру на небольшой белой подложке. Это относится к предпросмотру, PNG, SVG, ZIP и макетам A5/A6. Используется коррекция ошибок H; белое поле не менее четырёх модулей и служебные элементы сохраняются. SVG содержит встроенное изображение и работает без внешних загрузок. Ссылка источника не меняется, ранее напечатанные QR продолжают работать. Перед тиражом проверьте пробную распечатку телефоном.

## Что означают числа

| Показатель | Значение |
|---|---|
| Входящие переходы | Зарегистрированные запросы входа: лендинг, индивидуальная ссылка или прямой печатный маршрут |
| Посещения лендинга | Серверные открытия посадочной страницы; прямой печатный переход сюда не входит |
| Сессии | Оценка анонимных сессий; 30 минут бездействия завершают сессию. Cookie связывает повторные открытия только после согласия |
| Клики VK/TG/MAX | Серверные переходы через внутренние маршруты; наличие приложения или успешная подписка не подразумеваются |
| Конверсия в клик | Сессии с посещением лендинга и хотя бы одним кликом / сессии с посещением лендинга × 100% |
| Подтверждённые результаты | Только вручную внесённые, импортированные или принятые по защищённому API данные |
| Сырые / очищенные | Все сохранённые события / события после исключения известных ботов, предпросмотров, повторов и подозрительных запросов |

Одновременные клики одного посетителя по VK и Telegram дают два клика и одну конвертированную сессию. Открытие `/r/код` — переход по URL, а не гарантированное сканирование камерой. Люди с отключёнными cookie, сменившие устройство или очистившие браузер не могут надёжно объединяться; скрытого fingerprinting нет. Без согласия текущая цепочка страницы и кнопок связывается временным подписанным идентификатором в URL; аналитическая cookie не сохраняется. Повторное открытие без такого контекста создаёт новую сессию. Число сессий не равно числу уникальных людей.

CSV «Общая статистика» содержит одну сводную строку по выбранным фильтрам, включая direct/unknown. Экспорты кампаний и источников содержат строки соответствующих групп. Сессии разных источников не следует суммировать для получения общего числа: одна сессия может взаимодействовать с несколькими рекламными входами.

Атрибуция: явный валидный источник → проверенные UTM → домен referrer → direct. Произвольная UTM не создаёт рекламный источник. Для сессии сохраняются первый и последний рекламные источники; отчёт по событиям использует атрибуцию на момент события. Не объединяйте независимые источники по одному `utm_source`, если требуется однозначное сопоставление.

Расход источника — полная указанная стоимость размещения, а не автоматически распределённый по дням расход. В отчёте за период она делится на события этого периода. Поэтому при сравнении коротких периодов учитывайте даты и полноту размещения. Нулевой знаменатель даёт «нет данных», не нулевую стоимость. Бюджет кампании — план, а не дополнительный расход поверх расходов её источников. Доход и ROMI/ROI без данных о доходе не вычисляются.

События сохраняют кампанию на момент входа/клика, а расходы кампании рассчитываются по текущему составу источников. Для нового размещения в другой кампании создавайте новый источник: перенос уже работающего источника не распределяет его исторические расходы между кампаниями. Подтверждения по clickId сохраняют кампанию клика, агрегаты только по коду — текущую кампанию источника.

## Контент, ссылки и конверсии

Черновик текстов редактируется в админке, доступен предпросмотр; публикация отдельно меняет публичную версию. Обычный текст безопасно выводится как текст, произвольный HTML не поддерживается. Глобальные ссылки можно переопределить на конкретном источнике. Разрешены только HTTPS-адреса поддерживаемых платформ; параметр запроса посетителя не становится произвольным адресом редиректа. История изменений ссылок и критические действия журналируются.

Передача источника/идентификатора клика в бота настраивается отдельно от обычной ссылки на сообщество. Схема postback, CSV и официальные ссылки описаны в [документации интеграций](docs/integrations.md). Telegram/MAX/VK-боты и CRM в этот проект не включены; сайт не узнаёт о подписке без данных от разрешённой интеграции.

Яндекс.Метрика необязательна: задайте номер счётчика в настройках или `YANDEX_METRIKA_ID`. Она загружается только после согласия. События `landing_view`, `click_vk`, `click_telegram`, `click_max` служат дополнительной аналитикой и не являются источником для собственной БД. Отказ от Метрики не отключает серверные перенаправления.

## Развёртывание на VPS

Нужен Linux VPS с Docker Engine и Docker Compose plugin. База и резервные копии должны размещаться в подходящей юрисдикции с учётом применимых требований к персональным данным. Ниже команды выполняются в каталоге проекта на VPS.

1. Скопируйте исходники и файл блокировки зависимостей. Создайте `.env` из примера и ограничьте доступ: `chmod 600 .env`.
2. Настройте DNS A-запись домена на IPv4 VPS. Если добавляете AAAA, IPv6 также должен вести на этот сервер. Откройте TCP 80/443, UDP 443 при использовании HTTP/3, и свой SSH-порт. Порт 5432 и 3000 публиковать не нужно.
3. Укажите `APP_URL=https://ваш-домен`, `CADDY_DOMAIN=ваш-домен` без протокола/пути, рабочий `CADDY_EMAIL`. Сгенерируйте разные случайные `AUTH_SECRET`, `POSTBACK_SECRET`, `POSTGRES_PASSWORD` через `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` или `openssl rand -hex 32`. Для пароля PostgreSQL используйте hex: Compose вставляет его в URL подключения. Не используйте примерные значения.
4. Выполните:

```sh
docker compose build
docker compose up -d db
docker compose run --rm migrate
docker compose run --rm app pnpm admin:create
# Необязательно: только если нужны четыре тестовых источника.
docker compose run --rm app pnpm db:seed
docker compose --profile maintenance up -d app caddy retention
docker compose ps
```

Миграции выполняются явно отдельной командой, повторный запуск безопасен. После успешного HTTPS-запуска проверьте `https://ваш-домен/api/health` (процесс) и `https://ваш-домен/api/ready` (БД). Caddy автоматически получает и продлевает сертификат; том `caddy_data` нужно сохранять. Если сертификат не выдаётся, проверьте DNS, входящий 80/443, отсутствие второго прокси на этих портах и `docker compose logs caddy`.

Приложение доступно только внутри Docker-сети через Caddy. `TRUST_PROXY=true` задан в Compose и позволяет доверять очищенным proxy-заголовкам. Не публикуйте порт приложения напрямую и не выставляйте это значение при запуске за недоверенным прокси. При дополнительном CDN сначала отдельно настройте и проверьте доверенную цепочку адресов; по умолчанию такая схема не настроена.

Образы Node/PostgreSQL/Caddy используют фиксированную major-версию и плавающий patch-тег. Для воспроизводимого промышленного выпуска закрепите проверенные image digest, затем обновляйте их планово. Зависимости JavaScript фиксируются `pnpm-lock.yaml`. Runtime намеренно содержит исходники, полный `node_modules`, TypeScript CLI и devDependencies, чтобы миграции, admin:create и очистка работали тем же образом, что приложение. Standalone output и урезанный production-only набор зависимостей не используются.

## Резервные копии и восстановление

```sh
sh scripts/backup.sh
```

Скрипт создаёт консистентный PostgreSQL custom-format дамп в `backups/`, не передавая пароль в аргументах хоста. Дамп содержит чувствительные административные данные: ограничьте доступ, шифруйте копии вне VPS и проверяйте восстановление на отдельной БД. Не считайте один Docker volume резервной копией. Скрипт не удаляет старые архивы автоматически; срок хранения и удаление копий организует владелец.

Пример ежедневного cron на VPS (замените каталог; проверяйте журнал и наличие файлов):

```cron
15 2 * * * cd /srv/motiv && sh scripts/backup.sh >> /srv/motiv-backup.log 2>&1
```

Восстановление **заменяет текущее содержимое БД**. Сначала сохраните свежий backup и остановите запись:

```sh
docker compose stop caddy app retention
ALLOW_DATABASE_RESTORE=I_UNDERSTAND sh scripts/restore.sh ./backups/motiv-ДАТА.dump
docker compose run --rm migrate
docker compose --profile maintenance up -d app caddy retention
```

Скрипт проверяет читаемость архива и восстанавливает в одной транзакции. Никогда не передавайте незнакомый dump без проверки: PostgreSQL restore исполняет содержимое доверенной резервной копии. Для локальной PGlite остановите все процессы перед копированием всего `.data/postgres`; `backup.sh` работает только с PostgreSQL из Compose.

## Очистка данных и обновления

`pnpm db:retention` удаляет подробные события и подтверждённые результаты старше выбранного в админке срока, устаревшие сессии и служебные ключи. По умолчанию подробная аналитика хранится 90 дней; журнал действий и история адресов — `AUDIT_RETENTION_DAYS` (365). Это удаление уменьшает исторические отчёты; постоянных обезличенных агрегатов пока нет. Отдельно управляйте сроком хранения backup, журналов VPS и сторонней аналитики. Контейнер `retention` запускает очистку сразу и далее каждые `MAINTENANCE_INTERVAL_SECONDS` (86400), проверяйте его журнал.

Обновление:

```sh
sh scripts/backup.sh
# Получите проверенную новую версию исходников, сохранив .env и volumes.
docker compose build
docker compose stop caddy app retention
docker compose run --rm migrate
docker compose --profile maintenance up -d app caddy retention
docker compose ps
```

Откат образа не откатывает схему. Сначала проверяйте совместимость миграции и сохранённого дампа. Не выполняйте `docker compose down -v` на рабочем сервере: команда удаляет тома БД и сертификатов.

## Границы MVP

- Фильтрация ботов и ограничение частоты — эвристики. Целенаправленный бот, имитирующий браузер, может пройти их; защиту от распределённой атаки дополните инфраструктурой VPS.
- Переход по ссылке не подтверждает подписку, получение задания или выплату. Подтверждённые агрегаты не означают уникальных людей; достоверность входных данных обеспечивает владелец/интеграция.
- Число сессий оценочное, зависит от согласия и cookie. Атрибуция не объединяет устройства.
- Нет готовых ботов, CRM, многопользовательских ролей, финансового учёта дохода/ROI и долговременных агрегатов после удаления событий.
- Списки источников/кампаний в админке пока загружаются целиком, без серверной пагинации. Экспорт событий ограничен 100000 строками, QR ZIP — 100 источниками. Высокая нагрузка и максимальная пропускная способность не измерялись.
- Встроенные браузеры и внешние приложения зависят от платформы. HTTPS-ссылки дают браузерный путь при отсутствии приложения, но полный переход/подписку на каждом реальном устройстве нужно проверить перед запуском.
- Конфигурация развёртывания подготовлена; успешный локальный build не заменяет пробный запуск Docker, миграций и восстановления на целевом VPS.

Подробные результаты и непроверенные внешние сценарии — в [docs/verification.md](docs/verification.md); устройство системы — в [docs/architecture.md](docs/architecture.md).
