# Ссылки, подтверждённые результаты и будущие интеграции

## Постоянные рекламные адреса

| Маршрут | Назначение |
|---|---|
| `/r/spb01` | Вход через источник, затем посадочная страница |
| `/v/spb01` | Прямой переход во ВКонтакте |
| `/t/spb01` | Прямой переход в Telegram |
| `/m/spb01` | Прямой переход в MAX |

Коды 2–32 символа: латинские строчные буквы, цифры, `_`, `-`, первый символ — буква или цифра. Короткий печатный код использует то же пространство имён. Например, источник `spb01` с печатным кодом `p01` доступен по `/r/spb01` и `/t/p01`. Старые адреса не переназначаются другому источнику. Изменение конечной ссылки не требует перепечатки QR. Неактивный источник сохраняет действующий URL; его события исключаются из очищенных показателей.

Источник может содержать индивидуальные конечные ссылки. Пустое значение использует глобальную настройку. У посетителя нет параметра `redirect=https://...`: разрешённые домены проверяются сервером и при сохранении, и при перенаправлении.

## Три режима передачи контекста

Для каждой площадки в настройках ссылок есть режим:

- `plain`: конечный HTTPS-адрес используется как задан; подходит для обычного сообщества, канала и индивидуальной пригласительной ссылки.
- `source`: в параметр запуска передаётся постоянный код источника, либо `direct`, если источника нет.
- `click`: передаётся короткий непрозрачный токен конкретного серверного клика `c_...`, который внешняя интеграция возвращает в postback.

Сервер устанавливает `start` для Telegram/MAX и `ref` для VK; для VK также `ref_source=motiv`. Режим перезаписывает одноимённый параметр в заданном URL. Для приглашений и ссылок со своим фиксированным payload выбирайте `plain`, чтобы сохранить исходный параметр.

Режим `source/click` имеет смысл только при наличии совместимого бота или сообщений сообщества. Он не превращает ссылку на обычный канал в интеграцию. Токен клика является идентификатором атрибуции, а не секретом авторизации. Не помещайте в URL ФИО, телефон, email, токены ботов или постбэка.

## Telegram

Официальная документация поддерживает `https://t.me/<bot_username>?start=<payload>`: до 64 символов `A–Z`, `a–z`, `0–9`, `_`, `-`. Наши код источника и токен клика укладываются в этот формат. Бот должен получить соответствующее `/start payload` через свой webhook, проверить доставку и отправить событие `bot_started` серверу. Обычное открытие сайта или нажатие нашей кнопки не считается стартом бота. Для подтверждения членства в сообществе нужна отдельная интеграция с необходимыми правами и событиями платформы.

Источник: [Telegram Bot Features — Deep Linking](https://core.telegram.org/bots/features#deep-linking), проверено 24.10.2026.

## MAX

Официальный формат бота — `https://max.ru/<botName>?start=<payload>`, до 128 символов. MAX передаёт `payload` в обновлении `bot_started`; webhook должен подписываться на этот тип. Наш MVP использует запуск бота, не `startapp` мини-приложения. Бот/его сервер принимает платформенный webhook, проверяет его подлинность в соответствии с MAX API и только затем вызывает наш postback. Бот в репозитории не реализован.

Источники: [MAX — Диплинки](https://dev.max.ru/help/deeplinks), [MAX — подготовка бота и payload](https://dev.max.ru/docs/chatbots/bots-coding/prepare), проверено 24.10.2026. Перед выпуском проверяйте ограничения и поддержку в актуальных клиентах платформы.

## ВКонтакте

Для сообщений сообщества предусмотрены ссылки `https://vk.me/<community>?ref=<payload>&ref_source=motiv`. Выберите конечной целью именно чат, если нужен этот контекст. Официальная схема VK API содержит поля `ref` и `ref_source` в сообщении; получение сообщения/обновления требует настройки API сообщества. Ссылка на обычную страницу `vk.com/<community>` сама по себе не подтверждает вступление и может не доставить метки боту.

Источники: [официальная схема сообщений VKCOM](https://github.com/VKCOM/vk-api-schema/blob/master/messages/objects.json), [официальный материал VK по REF-разметке ссылок на чат сообщества](https://object2-ac.vk-apps.com/vk-education-0554ff56-27eb-4093-a702-685722cef6d9/media/91/6b9101abe2f54a788fedfc39f9b04fb8.pdf), проверено 24.10.2026. Основной сайт dev.vk.com из среды разработки недоступен; перед боевой интеграцией проверьте текущую версию API и реальные callback-события своего сообщества.

## Подтверждённые конверсии

Поддерживаемые типы:

| Значение | Смысл |
|---|---|
| `subscribed` | Подписка, подтверждённая внешней системой/владельцем |
| `bot_started` | Реальный запуск бота |
| `task_started` | Пользователь приступил к заданию |
| `first_paid_task` | Выполнено первое оплачиваемое задание |
| `lead` | Подтверждённый лид по определению владельца |

`count` — число подтверждённых результатов в записи, не автоматически проверенные уникальные люди. Разные типы могут относиться к одному человеку, их нельзя бездумно суммировать в число лидов. Показатель подтверждённых результатов в dashboard суммирует все типы, а стоимость лида использует только `lead`. Идемпотентность защищает от повтора записи с одним `externalId` в рамках канала приёма (`postback`, `import`, ручной ввод), но не от разных ID или повторного внесения одного результата другим каналом.

Это пространство `origin`, а не пространство отдельного провайдера: все поставщики postback используют общий префикс `postback:`. Включайте имя системы в собственный ID (`telegram:event-123`, `crm:event-123`), чтобы независимые поставщики не подавляли события друг друга. При передаче одного реального события разными каналами организуйте дедупликацию у себя.

Вручную добавляйте результаты только при наличии подтверждающих сведений. Не подменяйте отсутствующие данные нулём. Установите собственное проверяемое определение `lead`, прежде чем сравнивать стоимость лидов. ROI/ROMI не вычисляются до отдельного добавления достоверных данных о доходе.

### Защищённый postback

`POST /api/postback`, JSON до 32 КиБ. Заголовки:

```http
Authorization: Bearer <POSTBACK_SECRET>
Content-Type: application/json
```

Тело запроса для агрегированного результата по источнику:

```json
{
  "externalId": "demo-bot-start-spb01-001",
  "sourceCode": "spb01",
  "type": "bot_started",
  "count": 1,
  "occurredAt": "2026-10-24T12:00:00+03:00"
}
```

Это пример для **тестового** источника, не сведения о реальном пользователе. Для более точной атрибуции вместо `sourceCode` отправьте `attribution` с токеном `c_...`, полученным ботом из режима `click`. Также принимается `clickId` (UUID события) или `sourceId` (UUID источника). Если передаёте несколько идентификаторов, они должны принадлежать одному источнику. Клик без известного источника не превращается в атрибутированную конверсию. Не передавайте одновременно несовместимые `attribution` и `clickId`.

`externalId` — обязательная строка 1–128 символов; создавайте детерминированный идентификатор из ID события вашей системы, без персональных данных. `count` — целое от 1 до 100000, по умолчанию 1. `occurredAt` необязателен: иначе используется время приёма; передавайте ISO 8601 с часовым поясом, дата не должна быть более чем на 5 минут в будущем. Слишком старые события могут сразу попасть под политику удаления.

Успех: HTTP 200, `{"inserted":true,"duplicate":false}`. Точный повтор в этом же канале: HTTP 200, `{"inserted":false,"duplicate":true}`. Повтор с тем же ID не обновляет количество, тип или дату. Ошибки: 400 — данные/источник/атрибуция, 401 — секрет, 413 — размер, 429 — частота, 503 — секрет не настроен. Текущий лимит endpoint — 120 запросов в минуту на технический ключ адреса; интеграция должна повторять временные ошибки с задержкой и неизменным `externalId`.

Секрет `POSTBACK_SECRET` (не менее 32 случайных символов) хранится только на серверах. Не вызывайте postback из браузера и не помещайте секрет в URL, CSV, логи или настройки публичного бота. Endpoint не принимает неподтверждённое событие из браузера как доказательство подписки; достоверность внешнего сообщения проверяет ваш адаптер платформы перед вызовом.

Пример серверного JavaScript, где секрет читается из окружения, а не записан в исходниках:

```js
const response = await fetch(`${process.env.APP_URL}/api/postback`, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.POSTBACK_SECRET}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    externalId: platformEventId,
    attribution: receivedStartPayload,
    type: 'bot_started',
    count: 1,
  }),
});
if (!response.ok) throw new Error(`Postback HTTP ${response.status}`);
```

`platformEventId` и `receivedStartPayload` в примере даёт ваш проверенный webhook-адаптер. Токены ботов, их webhook и верификация платформы не входят в сайт. При ротации общего секрета обновите обе стороны; отдельные API-ключи для разных интеграций — следующий этап развития.

### Импорт CSV

Импорт выполняется из защищённой админки, UTF-8 с необязательным BOM, разделитель — запятая. Заголовки:

```csv
external_id,source_code,type,count,occurred_at
demo-confirmed-spb01-001,spb01,bot_started,1,2026-10-24T12:00:00+03:00
demo-confirmed-spb02-001,spb02,lead,1,2026-10-24T12:00:00+03:00
```

Обе строки относятся к тестовым источникам. Каждый ID сохраняется при повторной выгрузке. Не генерируйте новый ID для того же результата. `occurred_at` можно оставить пустым; тогда применяется время импорта. Остальные поля должны быть заполнены. Ограничение — 1 МБ и 5000 строк за один импорт; API-обёртка JSON также ограничена 1 МБ, поэтому используйте файлы с запасом меньше этого размера.

Валидация всех строк выполняется до записи. Ошибка строки отменяет весь импорт и указывает номер строки; правильный импорт записывается транзакционно. Ответ содержит число `inserted` и `duplicates`; точные повторы ID внутри канала импорта не увеличивают счётчик. Если внешняя система даёт только общую сумму без источника и совместимого идентификатора, достоверная атрибуция к рекламному источнику невозможна.

## Контроль перед интеграцией

Проверяйте событие сначала на тестовом источнике; его результат должен оставаться в тестовом режиме отчёта. Затем повторите тот же postback и убедитесь, что количество не выросло. Отдельно проверьте неверный секрет, неизвестный источник, несовпадение источника и clickId, превышение лимита и повтор webhook от платформы. Источники реального трафика не должны использоваться для демонстрационных запросов.
